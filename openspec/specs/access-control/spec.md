# Access Control

Права доступа определяются ролями пользователя и моделью скрытия организаций.
Менеджер по умолчанию видит все организации, кроме скрытых администратором
(ADR-0012). Администратор видит всё и управляет скрытием (ADR-0008).
Механика аутентификации и проверки текущего пользователя — в спецификации
`authentication`.

## Purpose

Определяет роли пользователей (admin, manager) и правила доступа к
организациям: менеджер видит все организации, кроме скрытых; администратор —
все организации без ограничений.

## Requirements

### Requirement: Система определяет роли пользователей
The system SHALL assign every user one of the fixed roles: admin or manager.
The role set SHALL be fixed: creating, changing, or deleting roles is not
supported (Roles CRUD endpoints are not implemented, see ADR-0009).

#### Scenario: Назначение роли при создании пользователя
- **WHEN** администратор создаёт пользователя "Мария Смирнова" и назначает ей роль manager
- **THEN** пользователь "Мария Смирнова" получает роль manager

#### Scenario: Система отклоняет создание произвольной роли
- **WHEN** аутентифицированный администратор пытается создать новую роль "supervisor"
- **THEN** система отклоняет операцию создания роли

### Requirement: Менеджер видит все организации, кроме скрытых
A manager SHALL by default have access to all organizations in the system.
The system SHALL exclude only organizations for which a hide record exists
for that manager. Group membership SHALL NOT affect access to organizations.

#### Scenario: Менеджер по умолчанию видит все организации
- **WHEN** администратор создаёт нового менеджера "Иван Петров"
- **AND** менеджер "Иван Петров" открывает список организаций
- **THEN** он видит все организации системы

#### Scenario: Скрытая организация не отображается менеджеру
- **WHEN** администратор скрыл организацию "ООО Конкурент" от менеджера "Иван Петров"
- **AND** менеджер "Иван Петров" выполняет поиск организаций
- **THEN** организация "ООО Конкурент" не отображается в результатах

#### Scenario: Скрытие побеждает членство в группах
- **WHEN** организация "ООО Ромашка" состоит в группе, созданной менеджером "Иван Петров"
- **AND** администратор скрыл организацию "ООО Ромашка" от менеджера "Иван Петров"
- **THEN** менеджер "Иван Петров" не видит организацию "ООО Ромашка"

#### Scenario: Скрытие побеждает создание организации
- **WHEN** менеджер "Иван Петров" создал организацию "ООО Новая"
- **AND** администратор скрыл организацию "ООО Новая" от менеджера "Иван Петров"
- **THEN** менеджер "Иван Петров" больше не видит организацию "ООО Новая"

### Requirement: Скрытие не ограничивает администратора
The administrator SHALL see all organizations regardless of hide records.
Hide records SHALL NOT restrict or modify administrator access in any way.

#### Scenario: Админ видит скрытые организации
- **WHEN** в системе есть организации, скрытые от разных менеджеров
- **AND** администратор открывает список организаций
- **THEN** он видит все организации, включая скрытые

### Requirement: Администратор видит все организации и группы
The administrator SHALL see all organizations and groups and SHALL manage
group membership and manager assignments. The administrator SHALL NOT have a
personal `user-<id>-group`; the access check for an administrator SHALL skip
groups.

#### Scenario: Админ видит все организации
- **WHEN** в системе существуют организации в разных группах и администратор открывает список организаций
- **THEN** он видит все организации без ограничений

#### Scenario: Админу не создаётся собственная группа
- **WHEN** администратор создаёт пользователя с ролью admin
- **THEN** для пользователя с ролью admin группа `user-<id>-group` не создаётся

#### Scenario: Админ управляет назначениями групп
- **WHEN** аутентифицированный администратор назначает и снимает группы менеджерам
- **THEN** изменения доступа применяются сразу
