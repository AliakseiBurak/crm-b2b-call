## Why

Проект стартует с пустого репозитория (ADR-0000): нет кода, окружения и
данных. Для разработки модулей (организации, контакты, обзвон, рассылки)
требуется воспроизводимое локальное окружение, которое любой разработчик
поднимает одной командой без ручной настройки.

## What Changes

- Добавляется `compose.yaml` с контейнерами: `php` (Symfony), `mysql`
  (БД), `mailpit` (dev-SMTP для приёма писем), `nginx` и `e2e`
  (Playwright-тесты проверки окружения).
- Создаётся пустой проект Symfony 7.4 LTS (текущий LTS-релиз; стек PHP 8.5,
  Doctrine ORM 3.x), подключаются Doctrine ORM и Symfony Mailer; зависимости
  ставятся через Composer.
- Выполняется начальная миграция — создание схемы БД.
- Загружаются фейковые данные (fixtures): пользователи (admin, менеджеры),
  группы организаций (`user-<id>-group`, custom), организации, контакты и
  запланированные звонки — для ручной проверки сценариев обзвона и рассылок.
- Сайт доступен по имени `https://b2b-crm.local` (только HTTPS, без
  HTTP, стандартный порт 443): запись в `/etc/hosts` хоста и самоподписанный
  CA + серверный сертификат с SAN `b2b-crm.local`, генерируемые скриптом в
  образе при первом старте и хранящиеся в named volume (пересборки
  сертификат не меняют).
- Самоподписанный CA устанавливается в доверенные сертификаты хост-машины
  (Linux) — браузер и curl не ругаются на сертификат.
- Добавляются Playwright-тесты (smoke): сайт отвечает, вход администратором
  и менеджером (`admin@b2b-crm.loc`/`admin123`,
  `manager@b2b-crm.loc`/`manager123`); запуск из сервиса `e2e` и из
  контейнера OpenCode (через `host.docker.internal`).
- Добавляется PHPMyAdmin (web-клиент БД, `http://localhost:8080`): работает
  внутри сети compose с `mysql` (`PMA_HOST`), порт хоста вынесен в `.env`
  (`PMA_PORT`), вход по кредам из `.env`.
- Добавляется локальная конфигурация окружения (`.env`/`.env.local`) и
  инструкция по запуску.

Изменение затрагивает только инфраструктуру разработки: поведение
возможностей CRM (организации, контакты, звонки, рассылки, доступ) не
меняется, поэтому `skip_specs: true` — spec-дельты не создаются.

## Capabilities

### New Capabilities
Нет — чисто инструментальное изменение (tooling/infrastructure), поведение
системы не меняется; включён `skip_specs: true` в `.openspec.yaml`.

### Modified Capabilities
Нет.

## Impact

- Корень репозитория: `compose.yaml`, `Dockerfile`, `nginx/` (TLS-конфиг),
  `docker/` (скрипты генерации сертификатов, entrypoint), `e2e/`
  (Playwright-конфиг и тесты), `.env`, `.env.example`, README с инструкциями
  запуска, `/etc/hosts` и установки CA.
- Зависимости: обновляется `composer.json` (Doctrine ORM, Symfony Mailer,
  fixtures-пакеты для разработки); dev-зависимость Playwright (@playwright/
  test) живёт в `e2e/` вне composer.
- Dev-окружение: `docker compose up` поднимает окружение одной командой;
  письма в dev уходят в Mailpit, реальный SMTP настраивается позже (ADR-0010).
- Хост-машина: запись `127.0.0.1 b2b-crm.local` в `/etc/hosts`; установка
  CA в системное хранилище доверенных сертификатов; доступ по
  `https://b2b-crm.local`.
- Прод: не затрагивается; инфраструктурные версии фиксируются в
  `compose.yaml` и `composer.json`.
