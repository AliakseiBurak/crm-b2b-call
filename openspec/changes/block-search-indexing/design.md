## Context

B2B Call CRM — Symfony 7.x приложение с Twig-шаблонами. Все страницы отрисовываются через общий базовый шаблон (`base.html.twig`). Приложение использует `form_login` для аутентификации, API — stateless с токенами. Сегодня ни HTTP-ответы, ни HTML-документы не содержат директив для поисковых систем.

См. proposal.md — Why для мотивации; specs/search-indexing/spec.md — требования.

## Goals / Non-Goals

**Goals:**
- Добавить `X-Robots-Tag: noindex, nofollow` ко всем HTTP-ответам единым механизмом
- Добавить `<meta name="robots" content="noindex, nofollow">` в базовый Twig-шаблон
- Гарантировать покрытие всех страниц: вход, welcome, дашборд, списки, формы, API

**Non-Goals:**
- Создание или修改 robots.txt (не критично для авторизованного приложения)
- Блокировка индексации через CSS/JS (избыточно при HTTP-заголовке)
- Изменение существующих контроллеров, шаблонов или маршрутов

## Decisions

### 1. Механизм добавления HTTP-заголовка: Event Subscriber vs Middleware

**Выбрано**: Symfony Event Subscriber на событие `kernel.response`.

**Альтернативы**:
- **Middleware (HttpKernelmiddleware)** — работает на уровне запроса/ответа, но для этого изменения достаточно модификации ответа, а не перехвата запроса. Subscriber проще в реализации и тестировании.
- **ResponseHeaderBag в каждом контроллере** — нарушает DRY; заголовок должен быть на ВСЕХ ответах, включая ошибки и редиректы.

**Rationale**: `kernel.response` — стандартный Symfony-механизм для модификации ответов. Subscriber является сервисом, который можно легко протестировать через functional tests. Покрывает все ответы независимо от контроллера, шаблона или маршрута.

### 2. Местоположение мета-тега: base.html.twig

**Выбрано**: Добавить тег в секцию `<head>` базового шаблона `templates/base.html.twig`.

**Альтернативы**:
- **Twig Extension / Function** — избыточно; мета-тег статичен и не зависит от контекста страницы.
- **Отдельный шаблон для мета-тегов** — нарушает простоту; один тег не оправдывает дополнительный файл.

**Rationale**: Базовый шаблон — единственная точка, через которую проходят все HTML-страницы. Статичный мета-тег в `<head>` — самый простой и надёжный подход.

### 3. Двойная защита (HTTP-заголовок + мета-тег)

**Выбрано**: Реализовать оба механизма.

**Rationale**: HTTP-заголовок работает для всех ответов (включая API и не-HTML). Мета-тег — резервный слой для crawlers, которые обрабатывают HTML, но игнорируют HTTP-заголовки (редкий случай, но возможен). Двойная защита не добавляет сложности и соответствует принципу defense-in-depth.

## Risks / Trade-offs

- **[Существующие тесты]** → Тесты, проверяющие заголовки ответов, могут упасть, если ожидают отсутствие `X-Robots-Tag`. Митигация: обновить тесты; проверить наличие тестов на заголовки перед внесением изменений.
- **[Кэширование]** → Если приложение использует HTTP-кэш (Varnish, CDN), убедиться, что `X-Robots-Tag` не_STRIPается промежуточными слоями. Митигация: документировать зависимость; при необходимости добавить `Cache-Control: no-store`.
- **[API-клиенты]** → API-клиенты (мобильные приложения, интеграции) получат заголовок `X-Robots-Tag`, но он не влияет на их поведение — заголовок предназначен только для crawlers. Митигация: не требуется.

## Migration Plan

1. Создать event subscriber, добавляющий заголовок `X-Robots-Tag`
2. Добавить мета-тег в `base.html.twig`
3. Написать/обновить functional tests
4. Развернуть в staging, проверить через `curl -I` что заголовок присутствует
5. Развернуть в production

Rollback: удалить subscriber и мета-тег; заголовок и мета-тег исчезнут со всех ответов.
