## Context

Текущее состояние: на дашборде `/dashboard` в раскрытых секциях организаций отображаются звонки с кнопками-заглушками «Изменить» и «Добавить звонок», ведущими на несуществующие маршруты (404). Сущность `Call` уже реализована с полной доменной моделью: организация (обязательный), контакт (опциональный), scheduledAt (планирование), madeAt (факт), madeBy (кто совершил), notes, isDeal, nextCall (самоссылка), campaignId. Доступ определяется моделью ADR-0005–0008 через организацию.

Ограничения:
- Дизайн-система: поля с оранжевым подчёркиванием, кнопки-пилюли, без теней
- Доступ: проверка области доступа через организацию звонка
- Валидация: обязательные поля organization, scheduledAt (при создании)
- Модальные окна: для быстрых правок без перезагрузки страницы
- Зависимость: organizations-crud (выбор организации), contacts-crud (выбор контакта)
- Специфика: модель результата — комбинация независимых полей (campaign + deal + nextCall)

## Goals / Non-Goals

**Goals:**
- CRUD-операции со звонками (создание, редактирование, удаление)
- Страницы форм и модальные окна
- Валидация полей с сообщениями на русском
- Проверка области доступа (менеджер/администратор)
- Выбор организации и контакта из доступных
- Фиксация результата звонка (рассылка/сделка/следующий звонок)
- Соответствие дизайн-системе

**Non-Goals:**
- CRUD для организаций и контактов (отдельные changes)
- Сеанс обзвона (сложный workflow, отдельный change)
- Планирование/напоминание (отдельный change)
- Запуск рассылок (отдельный change)

## Decisions

### 1. Raw Twig формы + Symfony Validator

**Решение**: Использовать существующий компонент `form_field.html.twig` для рендеринга полей и Symfony Validator для валидации.

### 2. Vanilla JavaScript для модальных окон

**Решение**: Реализовать модальные окна на чистом JavaScript, как существующий `dashboard-search.js`.

### 3. CallController с проверкой доступа

**Решение**: Один контроллер с действиями new, create, edit, update, delete. Проверка доступа через организацию звонка: `OrganizationRepository::findAccessibleIds()` + проверка `call->organization->id` в списке доступных.

### 4. Выбор организации и контакта

**Решение**: При создании звонка показать выпадающий список организаций, доступных пользователю. При выборе организации — загрузить контакты этой организации через AJAX. Поле контакта опционально.

### 5. Модель результата звонка

**Решение**: Реализовать три независимых checkbox/select: рассылка (выпадающий список из существующих рассылок), сделка (checkbox), следующий звонок (дата). Все три опциональны, могут комбинироваться.

### 6. Каскадное удаление через Doctrine

**Решение**: Использовать `onDelete: 'SET NULL'` для contact и `onDelete: 'CASCADE'` для organization (уже настроено в БД).

## Risks / Trade-offs

- **Модальные окна без AJAX**: Данные формы загружаются в HTML страницы, что увеличивает размер. Mitigation: использовать делегирование событий и загружать данные только при открытии.
- **Валидация на клиенте**: Отсутствует в модальных окнах. Mitigation: серверная валидация через AJAX, показ ошибок в модальном окне.
- **Зависимость от organizations-crud и contacts-crud**: Форма создания звонка требует выбора организации и контакта. Mitigation: эти два changes должны быть реализованы первыми.
- **Динамическая загрузка контактов**: Может быть медленной при большом количестве контактов. Mitigation: кэширование, лимит на количество.
- **Удаление без undo**: После подтверждения удаление необратимо. Mitigation: модальное окно подтверждения.
