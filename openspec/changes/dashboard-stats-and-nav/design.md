## Context

Symfony 7.4, Doctrine ORM (MySQL), Twig + Webpack Encore, один монолитный
контейнер. Текущее состояние: `HomeController` отдаёт `/` и `/dashboard`
без данных; шапка содержит CTA «Позвонить»/«Создать» и зелёную градиентную
полосу меню; welcome page содержит промо-блок и карточки курсов; модалка
«Заказать звонок» в `base.html.twig`. Модель доступа: менеджер — только
организации своих групп (`user-<id>-group` + assigned custom), админ — все
(ADR-0005–0008). Сущность `Call`: `made_at` (факт звонка), `scheduled_at`
(план), `is_deal`, `next_call`, `organization`.

Мотивация — proposal.md «Why».

```

                    [ Browser ]
                        |
                        v
              [ HomeController::dashboard() ]
                        |
        +---------------+---------------+
        |                               |
        v                               v
[ OrganizationRepository ]      [ CallRepository::dashboardStats() ]
   (id-область менеджера,            (6 COUNT(CASE) по `call`,
    ADR-0007; admin=nul)              фильтр по :orgIds|null)
        |                               |
        +---------------+---------------+
                        v
                 [ MySQL: `call`, оrg_grouo_membership,
                   group_assignment ]
                        |
                        v
              [ dashboard.html.twig → .stats-виджеты ]
```

## Goals / Non-Goals

Goals:
- Дашборд `/dashboard` показывает 6 показателей из реальных данных `Call` с учётом области доступа.
- Шапка: логотип слева (→ главная), пункты навигации в верхней строке (без градиентной полосы), справа для вошедших — кнопки «Создать организацию»/«Создать контакт» (ссылки-заглушки).
- Удаление маркетингового слоя: модалка, CTA «Позвонить»/«Создать», «Заказать звонок», промо, карточки курсов.
- Фикстуры со звонками в периодах; e2e-проверки.

Non-Goals:
- CRUD организаций/контактов (кнопки — ссылки-заглушки, формы не создаются).
- Другие страницы статистики, графики, экспорт.
- Изменения доменной модели (`Call`, `Organization`, `Contact` не трогаются) и ADR.

## Decisions

### D1. Один метод `CallRepository::dashboardStats()`

`dashboardStats(?\DateTimeImmutable $from = null, ...)` — один DQL-запрос
на все 6 показателей через `COUNT(CASE WHEN ...)` + `GROUP BY`-агрегацию,
с фильтром по области доступа в `WHERE`.

Почему один запрос: 6 отдельных COUNT по таблице `call` на каждый показ
страницы — лишние round-trips; таблица небольшая, один проход дешевле.
Альтернатива (6 COUNT-подзапросов) отклонена из-за N+1-подобного
поведения и менее читаемого SQL.

Периоды (календарные, согласовано в спеке):
- Обзвонено: `made_at` ≥ начало дня (сегодня), ≥ начало дня − 6 дней
  (7 дней), ≥ начало дня − 29 дней (30 дней).
- Ждут обзвона: `scheduled_at` в [начало дня, конец дня] (сегодня);
  в [сейчас, сейчас + 7 дней] и [сейчас, сейчас + 30 дней].

### D2. Скоуп доступа через «доступные организации»

`CallRepository::dashboardStats()` принимает `?array $organizationIds` =
`null` (админ — все) или список id организаций менеджера. Список строится
в `HomeController::dashboard()` через `OrganizationRepository` (или новый
метод `findAccessibleIds(User $user)`), объединяя организации
`user-<id>-group` и assigned custom groups менеджера (ADR-0007; без новых
ACL-механизмов и per-org тиров).

Фильтр в DQL: `WHERE c.organization IN (:ids)` для менеджера, без
фильтра для админа. Организации вне области просто не попадают в выборку
— никакого 403 на дашборде (это не действие, а агрегация).

### D3. Навигация — единый `base.html.twig`

- `menu` для шапки задаётся в `base.html.twig`: вошедшие — «Панель»,
  «Выйти»; гости — «Войти». Пункт «Главная» убирается (его роль играет
  логотип). Пункты рендерятся компонентом `header.html.twig` в верхней
  строке (инлайн-список), зелёная полоса удаляется.
- Кнопки «Создать организацию»/«Создать контакт» — для `app.user`, в
  правой части `header__top`, ссылки на `/organizations/new` и
  `/contacts/new` (заглушки: маршруты не существуют → 404 до реализации
  CRUD отдельным изменением).
- `header.html.twig` получает параметры `menu` и `createActions`.

Альтернатива (оставить полосу, убрать только пункт «Главная») отклонена
по решению пользователя: полоса убирается полностью.

### D4. Удаление маркетингового слоя

- `base.html.twig`: удаляется `{% embed modal.html.twig %}` (модалка
  «Заказать звонок»), связанный JS (`call-request.js`, modal.js).
- `home/index.html.twig`: удаляются промо-секция «Как это работает»,
  секция карточек курсов с `offer_card.html.twig` и `btn--all`; остаются
  hero (убирается вторичная кнопка «Заказать звонок») и блок статистики.
- Компонент `modal.html.twig` удаляется целиком вместе со стилями
  (`_modal.scss`, modal.js) — спека `web-interface` требует модалки REMOVED.
- `offer_card.html.twig`, `card.html.twig`, `table.html.twig`, `btn--all`
  остаются в коде как готовые компоненты (спека сохраняет требования
  «Контактные карточки»/«Таблицы»); удаляются только вызовы с текущих
  страниц. SCSS-ветки, ставшие мёртвыми (promo, offer-card, cta-bar,
  header__menu-полоса), удаляются.

### D5. Фикстуры звонков

`AppFixtures` получает звонки с `made_at`/`scheduled_at` по организациям:
сегодня, вчера, 6–7 дней, 29–30 дней назад, плюс запланированные на
сегодня/через 3/20 дней — так все 6 показателей ненулевые и проверяемые.
Часть звонков — «вне области» менеджера (организация только в группе
другого менеджера/без назначений менеджеру), чтобы проверялся скоуп
(ADR-0007) в e2e.

### D6. Дизайн дашборда

`dashboard.html.twig`: заголовок h1 «Панель» + блок «Обзвонено» (3
виджета: сегодня/7 дней/30 дней) на зелёной градиентной ленте
(`.stats`-стили, числа 56px bold по типографике welcome), ниже белая
секция «Ждут обзвона» (3 виджета: сегодня/неделя/месяц) с числами
оранжевым акцентом. Переиспользуются существующие SCSS-классы
(`.stats`, `.section--white`, цвета из палитры); новых больших стилей не
требуется.

## Risks / Trade-offs

- [Шесть разных периодов → расхождение «календарное vs скользящее»] →
  зафиксировано в спеке: «сегодня» — календарные сутки; проверяется e2e.
- [DQL агрегация сложна для отладки] → один читаемый запрос с CASE,
  покрытёр контент-тестом (fixtures → числа).
- [Удаление модалки ломает старые e2e/спеки] → тесты обновляются в этом
  же change; старая спека `web-interface` уже синхронизирована (REMOVED).
- [Заглушки `/organizations/new` 404 → кнопка «битая»] → принято
  пользователем до реализации CRUD; ссылки реальны и станут рабочими
  после CRUD-изменения.

## Migration Plan

- БД: только фикстуры (`php bin/console doctrine:fixtures:load` для
  dev/теста) — миграций нет.
- Фронт: `npm run build` (public/build обновляется automatically на живом
  сайте).
- Откат: revert коммитов кода затем пересборка assets; данные фикстур —
  перезагрузка пустой БД (dev).
