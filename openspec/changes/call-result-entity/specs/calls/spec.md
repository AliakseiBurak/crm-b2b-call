## MODIFIED Requirements

### Requirement: Результат звонка
The call result SHALL be optional. When present, the result SHALL be stored as a `CallResult` record with a fixed type (`new_call`, `no_answer_new_call`, `refusal`, `refusal_mailing`, `mailing`, `dealing`). Each type MAY have associated fields: `mailing` and `refusal_mailing` reference a campaign; `new_call` and `no_answer_new_call` reference a newly created call; `refusal` and `dealing` have no additional fields. A result MAY include notes.

#### Scenario: Результат — рассылка
- **WHEN** менеджер завершает звонок по организации «ООО Ромашка»
- **AND** выбирает тип результата «рассылка»
- **AND** выбирает кампанию «Новые курсы»
- **THEN** создаётся `CallResult` с типом `mailing` и ссылкой на кампанию «Новые курсы»
- **AND** звонок организации «ООО Ромашка» получает ссылку на этот результат

#### Scenario: Результат — отказ-рассылка
- **WHEN** менеджер завершает звонок по организации «ООО Ромашка»
- **AND** выбирает тип результата «отказ-рассылка»
- **AND** выбирает кампанию «Новые курсы»
- **THEN** создаётся `CallResult` с типом `refusal_mailing` и ссылкой на кампанию «Новые курсы»

#### Scenario: Результат — сделка
- **WHEN** менеджер завершает звонок по организации «ООО Ромашка»
- **AND** выбирает тип результата «сделка»
- **THEN** создаётся `CallResult` с типом `dealing`

#### Scenario: Результат — будущий звонок
- **WHEN** менеджер завершает звонок по организации «ООО Ромашка»
- **AND** выбирает тип результата «новый звонок»
- **AND** указывает дату следующего звонка
- **THEN** создаётся `CallResult` с типом `new_call` и ссылкой на новый звонок с указанной планируемой датой
- **AND** организация «ООО Ромашка» попадает в планирование

#### Scenario: Результат — нет ответа, новый звонок
- **WHEN** менеджер завершает звонок по организации «ООО Ромашка»
- **AND** выбирает тип результата «нет ответа — новый звонок»
- **AND** указывает дату следующего звонка
- **THEN** создаётся `CallResult` с типом `no_answer_new_call` и ссылкой на новый звонок с указанной планируемой датой

#### Scenario: Результат — отказ
- **WHEN** менеджер завершает звонок по организации «ООО Ромашка»
- **AND** выбирает тип результата «отказ»
- **THEN** создаётся `CallResult` с типом `refusal`

#### Scenario: Комбинация результатов
- **WHEN** менеджер завершает звонок по организации «ООО Ромашка»
- **AND** ранее модель позволяла одновременно отмечать рассылку, сделку и следующий звонок
- **THEN** по новой модели фиксируется ровно один результат из шести типов (рассылка, отказ-рассылка, сделка, новый звонок, нет ответа — новый звонок, отказ); комбинирование отметок не допускается

#### Scenario: Звонок без результата
- **WHEN** менеджер завершает звонок по организации «ООО Ромашка»
- **AND** не выбирает тип результата
- **THEN** фиксируется только факт звонка (кто и когда)
- **AND** result_id звонка остаётся пустым

#### Scenario: Заметка к результату
- **WHEN** менеджер фиксирует результат звонка
- **AND** вводит заметку
- **THEN** заметка сохраняется в записи `CallResult`

### Requirement: Сущность звонка
The system SHALL store a call with an organization, an optional contact, a scheduled date, the fact of the call (who made it and when), optional notes, and an optional reference to a `CallResult`.

#### Scenario: Запланированный звонок
- **WHEN** в системе существует организация «ООО Ромашка» и контакт «Иван Петров»
- **AND** менеджер планирует звонок контакту «Иван Петров» на завтра
- **THEN** звонок сохраняется с датой «завтра»

#### Scenario: Фиксация факта звонка
- **WHEN** менеджер «Иван Петров» провёл звонок контакту организации «ООО Ромашка»
- **AND** отмечает дату и время звонка
- **THEN** в истории звонков организации отображается, что звонок осуществил менеджер «Иван Петров» в указанные дату и время
