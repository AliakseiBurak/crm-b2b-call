# Design: openspec-single-source-of-truth

## Context

Изменение `reconcile-specs-with-prd` привело спецификации в соответствие с PRD и
зафиксировало решение о ролях (ADR-0005). Следующий шаг перехода: объявить OpenSpec
единственным источником истины (ADR-0006), зафиксировать сознательно отложенные
пробелы, чтобы удаление PRD ничего не потеряло, устранить ссылки «PRD §…» в
контексте ADR-0001–0004 и перенести план разработки из PRD §8 в задачи.

```
        текущее состояние                        целевое состояние
┌──────────────────────────┐              ┌─────────────────────────────┐
│ PRD.md (docs/source)     │  ────удал.──▶│  (файл удалён)              │
│   └── ссылки в ADR-1..4  │  ──перепис.──▶│  ADR-1..4: Context → specs │
│   └── §8 план разработки │  ──в tasks──▶│  change tasks.md           │
│   └── §7/§6.3 пробелы    │  ──ADR-0006──▶│  реестр отложенных пробелов│
└──────────────────────────┘              └─────────────────────────────┘
```

## Goals / Non-Goals

**Goals:**
- ADR-0006: OpenSpec — единственный источник истины; PRD удаляется.
- Реестр отложенных пробелов (users, NFR, CSRF) — зафиксирован, не потерян.
- Контекст ADR-0001–0004 ссылается на спецификации, а не на удаляемый PRD.
- План разработки PRD §8 перенесён в проверяемые задачи.

**Non-Goals:**
- НЕ создавать новые возможности/спецификации (пробелы отложены, а не
  реализованы).
- НЕ изменять поведение спецификаций (`skip_specs: true`).
- НЕ удалять файлы PRD (это change `remove-prd-sources`).

## Decisions

**D1. ADR-0006 фиксирует переход и реестр отложенных пробелов.**
Отложены и явно перечислены: детали сущности `User` (PRD §2.10 — CRUD
пользователей, связь `own_group_id`), NFR «доступность 99.5%, ежедневный бэкап,
аудит-логирование» (PRD §7), CSRF-защита (PRD §6.3). Это гарантирует, что
удаление PRD не «теряет» требования молча: они задокументированы как будущая
работа. Альтернатива (реализовать всё сейчас) противоречит выбору пользователя
«minimal: document only».

**D2. Переписывание контекста ADR-0001–0004.**
Схема OpenSpec объявляет ADR неизменяемыми («IRON RULE»). Пользователь явно
выбрал переписывание контекста, понимая потерю исторической точности (см.
proposal). Причина оправдана: PRD будет удалён, ссылки «PRD §…» станут висячими.
Правим ТОЛЬКО секцию Context (ссылки на источники), не трогая Decision и
Consequences. Отклонение фиксируется в ADR-0006 и proposal.

**D3. План PRD §8 переносится в tasks.md как задачи-чеки.**
Этапы «MVP», «Рассылки», «Звонки и анализ», «Интеграции и настройки» становятся
разделами tasks.md с проверяемыми пунктами. Это roadmap-контекст, не требования.

## Risks / Trade-offs

- [Нарушение неизменяемости ADR] -> Пользователь выбрал переписывание осознанно;
  отклонение задокументировано в ADR-0006; Decision/Consequences не меняются.
- [Висячие ссылки после удаления PRD] -> ADR-0006 создаётся до удаления; контекст
  ADR-0001–0004 переписан; оставшиеся ссылки вычищаются в change
  `remove-prd-sources`.
- [Потеря требований] -> Реестр отложенных пробелов в ADR-0006 исчерпывающ.

## Migration Plan

1. Создать `adr/0006-openspec-single-source-of-truth.md` и манифест `adr.md`.
2. Переписать секции Context ADR-0001–0004 (ссылки на `access-control` и
   `organization-groups` спецификации).
3. Заполнить tasks.md (порт §8 + проверки). Применить change, заархивировать.
4. Затем change `remove-prd-sources`: физическое удаление PRD и правка
   project.md/config/AGENTS.
