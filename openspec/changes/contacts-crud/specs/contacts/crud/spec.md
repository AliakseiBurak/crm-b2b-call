## Purpose

CRUD-операции с контактами: создание, редактирование, удаление через формы, соответствующие дизайн-системе, с привязкой к организации и проверкой области доступа.

## ADDED Requirements

### Requirement: Администратор создаёт контакт
The system SHALL let the administrator create a contact with all fields through a form, and SHALL validate required fields.

#### Scenario: Успешное создание контакта
- **WHEN** администратор открывает форму создания контакта
- **AND** выбирает организацию "ООО Ромашка"
- **AND** вводит имя "Иван Петров", телефон, email, должность, тип "физическое лицо"
- **AND** нажимает кнопку "Создать"
- **THEN** контакт "Иван Петров" сохраняется в системе
- **AND** администратор перенаправляется на страницу контакта

#### Scenario: Ошибка валидации при создании
- **WHEN** администратор открывает форму создания контакта
- **AND** оставляет поле "Имя" пустым
- **AND** нажимает кнопку "Создать"
- **THEN** форма отображает ошибку "Имя обязательно для заполнения"
- **AND** контакт не сохраняется

### Requirement: Менеджер создаёт контакт в доступной организации
The system SHALL let the manager create a contact only in organizations visible to them (own `user-<id>-group` + assigned groups).

#### Scenario: Менеджер создаёт контакт
- **WHEN** менеджер открывает форму создания контакта
- **AND** выбирает доступную организацию "ООО Ромашка"
- **AND** вводит имя "Иван Петров"
- **AND** нажимает кнопку "Создать"
- **THEN** контакт "Иван Петров" сохраняется в системе
- **AND** контакт привязывается к организации "ООО Ромашка"

#### Scenario: Менеджер не может создать контакт в невидимой организации
- **WHEN** менеджер пытается создать контакт в организации "ООО Завод"
- **AND** организация отсутствует в области доступа менеджера
- **THEN** система отклоняет запрос с ошибкой доступа

### Requirement: Администратор редактирует контакт
The system SHALL let the administrator update contact fields through a form.

#### Scenario: Успешное редактирование контакта
- **WHEN** администратор открывает форму редактирования контакта "Иван Петров"
- **AND** изменяет телефон на "+7-900-111-11-11"
- **AND** нажимает кнопку "Сохранить"
- **THEN** телефон контакта становится "+7-900-111-11-11"
- **AND** администратор перенаправляется на страницу контакта

#### Scenario: Ошибка валидации при редактировании
- **WHEN** администратор открывает форму редактирования контакта "Иван Петров"
- **AND** очищает поле "Имя"
- **AND** нажимает кнопку "Сохранить"
- **THEN** форма отображает ошибку "Имя обязательно для заполнения"
- **AND** контакт не обновляется

### Requirement: Менеджер редактирует видимый контакт
The system SHALL let the manager update only contacts of organizations visible to them.

#### Scenario: Менеджер редактирует видимый контакт
- **WHEN** менеджер открывает форму редактирования контакта "Иван Петров"
- **AND** контакт принадлежит доступной организации
- **AND** изменяет телефон на "+7-900-111-11-11"
- **AND** нажимает кнопку "Сохранить"
- **THEN** телефон контакта становится "+7-900-111-11-11"

#### Scenario: Менеджер не может редактировать невидимый контакт
- **WHEN** менеджер пытается открыть форму редактирования контакта "ООО Завод"
- **AND** контакт принадлежит организации, отсутствующей в области доступа
- **THEN** система отклоняет запрос с ошибкой доступа

### Requirement: Удаление контакта
The system SHALL let the administrator and managers delete contacts they have access to.

#### Scenario: Успешное удаление контакта
- **WHEN** администратор нажимает кнопку "Удалить" на странице контакта "Иван Петров"
- **AND** подтверждает удаление
- **THEN** контакт "Иван Петров" удаляется из системы
- **AND** администратор перенаправляется на список контактов организации

#### Scenario: Отмена удаления контакта
- **WHEN** администратор нажимает кнопку "Удалить" на странице контакта "Иван Петров"
- **AND** отменяет удаление
- **THEN** контакт "Иван Петров" остаётся в системе

### Requirement: Модальное окно быстрого редактирования
The system SHALL provide a modal window for quick contact editing from the dashboard without page reload.

#### Scenario: Открытие модального окна
- **WHEN** пользователь нажимает кнопку "Изменить" на карточке контакта на дашборде
- **THEN** открывается модальное окно с формой редактирования контакта
- **AND** данные контакта загружаются в форму

#### Scenario: Сохранение изменений в модальном окне
- **WHEN** пользователь изменяет телефон в модальном окне
- **AND** нажимает кнопку "Сохранить"
- **THEN** изменения сохраняются
- **AND** модальное окно закрывается
- **AND** карточка контакта на дашборде обновляется без перезагрузки страницы

#### Scenario: Закрытие модального окна
- **WHEN** пользователь нажимает кнопку "Отмена" или крестик в модальном окне
- **THEN** модальное окно закрывается
- **AND** изменения не сохраняются

### Requirement: Форма соответствует дизайн-системе
The system SHALL render contact forms with the established design system: underline inputs, pill buttons, no shadows.

#### Scenario: Поле формы с оранжевым подчёркиванием
- **WHEN** пользователь открывает форму контакта
- **THEN** каждое текстовое поле отображается без рамки и фона
- **AND** под полем — линия толщиной 2px цвета `#d66a2b`
- **AND** текст и плейсхолдер поля окрашены в `#d66a2b`

#### Scenario: Кнопки формы
- **WHEN** пользователь открывает форму контакта
- **THEN** кнопка "Создать/Сохранить" — оранжевая градиентная пилюля
- **AND** кнопка "Отмена/Удалить" — серая пилюля
