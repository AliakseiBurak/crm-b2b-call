## Context

Текущее состояние: на дашборде `/dashboard` отображаются карточки контактов с кнопками-заглушками «Изменить» и «Добавить контакт», ведущими на несуществующие маршруты (404). Сущность `Contact` уже реализована с полной доменной моделью (name, phone, email, position, contactType, contactPerson, notes). Контакт привязан ровно к одной организации через внешний ключ `organization_id`. Доступ определяется моделью ADR-0005–0008: менеджер видит контакты организаций своих групп, администратор — все.

Ограничения:
- Дизайн-система: поля с оранжевым подчёркиванием, кнопки-пилюли, без теней
- Доступ: проверка области доступа через организацию контакта
- Валидация: обязательные поля name, organization, contactType
- Модальные окна: для быстрых правок без перезагрузки страницы
- Зависимость: organizations-crud (выбор организации при создании)

## Goals / Non-Goals

**Goals:**
- CRUD-операции с контактами (создание, редактирование, удаление)
- Страницы форм и модальные окна
- Валидация полей с сообщениями на русском
- Проверка области доступа (менеджер/администратор)
- Выбор организации из доступных при создании
- Соответствие дизайн-системе

**Non-Goals:**
- CRUD для организаций (отдельный change organizations-crud)
- Группировка контактов (контакты привязаны к одной организации)
- Импорт/экспорт контактов
- Массовое удаление

## Decisions

### 1. Raw Twig формы + Symfony Validator

**Решение**: Использовать существующий компонент `form_field.html.twig` для рендеринга полей и Symfony Validator для валидации.

### 2. Vanilla JavaScript для модальных окон

**Решение**: Реализовать модальные окна на чистом JavaScript, как существующий `dashboard-search.js`.

### 3. ContactController с проверкой доступа

**Решение**: Один контроллер с действиями new, create, edit, update, delete. Проверка доступа через организацию контакта: `OrganizationRepository::findAccessibleIds()` + проверка `contact->organization->id` в списке доступных.

### 4. Выбор организации из доступных

**Решение**: При создании контакта показать выпадающий список организаций, доступных пользователю. Для администратора — все организации, для менеджера — только организации его групп.

### 5. Каскадное удаление через Doctrine

**Решение**: Использовать `onDelete: 'CASCADE'` в Doctrine mapping для контакта (уже настроено в БД).

## Risks / Trade-offs

- **Модальные окна без AJAX**: Данные формы загружаются в HTML страницы, что увеличивает размер. Mitigation: использовать делегирование событий и загружать данные только при открытии.
- **Валидация на клиенте**: Отсутствует в модальных окнах. Mitigation: серверная валидация через AJAX, показ ошибок в модальном окне.
- **Зависимость от organizations-crud**: Форма создания контакта требует выбора организации. Mitigation: organizations-crud должен быть реализован первым.
- **Удаление без undo**: После подтверждения удаление необратимо. Mitigation: модальное окно подтверждения.
