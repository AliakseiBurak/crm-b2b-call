# Proposal: reconcile-specs-with-prd

## Why

`docs/source/PRD.md` удаляется: единственным источником истины становится OpenSpec.
Перед удалением необходимо привести все 10 существующих спецификаций возможностей
в соответствие с PRD, чтобы никакие требования не потерялись, и заменить ссылки
«Источник: PRD.md §…» на ссылки внутри OpenSpec (спецификации и ADR). Заодно
разрешается внутреннее противоречие PRD (§2.10/§3.7 — роли как фиксированный
enum; §4.5 — CRUD-эндпоинты ролей).

## What Changes

- **`access-control`**: уточнено правило назначения ролей — набор ролей
  фиксирован (admin, manager, operator), CRUD ролей не вводится (разрешение
  противоречия PRD §2.10/§3.7 vs §4.5).
- **`email-campaigns`**: уточнено, что рассылка создаётся в рамках организации и
  доставляется по группе контактов (охватывает поле `organization_id` из §2.6).
- **Остальные 8 возможностей**: поведение не меняется; расхождения отсутствуют
  (результат ревью, см. design.md — матрица сверки). Удаление строк-источников
  «PRD.md §…» из спецификаций выполняется в change `remove-prd-sources`.
- **`contacts`**: сценарий удаления контакта — обоснованное расширение (в PRD
  §4.2 нет DELETE), изменения не требуются.
- **Новый ADR-0005**: роли — фиксированный enum; эндпоинты Roles CRUD из §4.5
  отброшены.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `access-control`: уточнение правила назначения ролей — фиксированный набор,
  без CRUD ролей
- `email-campaigns`: уточнение области действия рассылки (организация + группа контактов)

## Impact

- `openspec/specs/*/spec.md` — заголовки-источники и точечные уточнения.
- Добавляется `adr/0005-roles-fixed-enum.md`.
- Код, API и зависимости не затрагиваются (рабочее пространство — документация).
- Подготавливает почву для удаления `docs/source/PRD.md` (change
  `openspec-single-source-of-truth`, `remove-prd-sources`).
