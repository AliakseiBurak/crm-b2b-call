# Proposal: openspec-single-source-of-truth

## Why

После reconciliation-изменения спецификации корректно отражают PRD. Теперь нужно
зафиксировать долгосрочное решение: **OpenSpec становится единственным источником
истины**, PRD удаляется. Это требует нового ADR (переход) и реестра отложенных
пробелов, чтобы удаление PRD не привело к потере требований.

## What Changes

- **Новый ADR-0006**: OpenSpec — единственный источник истины; PRD удаляется
  (change `remove-prd-sources`); реестр сознательно отложенных пробелов:
  - детали сущности `User` (PRD §2.10) — не выносятся в отдельную возможность;
  - NFR «доступность 99.5%, ежедневное резервное копирование, полное
    логирование для аудита» (PRD §7);
  - CSRF-защита (PRD §6.3);
  Пробелы — будущая работа, не требования текущего скоупа.
- **Переписывание контекста ADR-0001–0004**: ссылки «PRD §…» заменяются на
  ссылки на спецификации возможностей (`access-control`, `organization-groups`).
  Осознанное отклонение от правила неизменяемости ADR в OpenSpec — по явному
  выбору пользователя (историческая точность контекста уже не поддерживается,
  т.к. PRD будет удалён).
- **Порт плана разработки (PRD §8)**: этапы MVP/рассылки/звонки/интеграции
  переносятся в tasks.md этого change как проверяемые задачи.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет. Поведенческих изменений спецификаций нет (`skip_specs: true`).

## Impact

- `adr/0006-openspec-single-source-of-truth.md` — новый ADR.
- `adr/0001–0004-*.md` — правка секции Context (ссылки на PRD → ссылки на specs).
- `openspec/changes/openspec-single-source-of-truth/tasks.md` — порт плана §8.
- Подготавливает удаление `docs/source/PRD.md` и `PRD_WORKFLOW.md` в change
  `remove-prd-sources`.
