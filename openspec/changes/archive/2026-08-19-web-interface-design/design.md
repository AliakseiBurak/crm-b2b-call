## Context

Уровень представления B2B Call CRM (Symfony 7.x, Twig, Webpack Encore) не
имеет единого визуального языка. Мотивация и объём — в `proposal.md` (Why);
проверяемые требования к стилям — в `specs/web-interface/spec.md`.
Текущих стилей уровня представления нет (изменение аддитивное). Доменные
сущности, правила доступа (`adr/0005–0008`), модель звонков (`adr/0004`) и
рассылок (`adr/0010`) не затрагиваются. Сборка активов (Encore) создаётся
отдельным изменением `asset-pipeline-setup` — данное изменение её потребляет.

## Goals / Non-Goals

**Goals:**
- Единая точка правды визуальных значений (токены) и компонентов интерфейса,
  адаптированная под продолжительную работу: мягкая палитра (та же гамма,
  приглушённые тона), фиксированные семантические роли цветов.
- Применение дизайна к welcome page, формам (включая страницу входа в общем
  шаблоне), контактным карточкам, кнопкам, таблицам, модальным окнам,
  шапке/подвалу.
- Проверяемость соответствия спецификации (точные hex-значения, размеры,
  отсутствие теней) автоматизированными проверками.

**Non-Goals:**
- Не вводится тёмная тема (см. spec).
- Не создаётся новая функциональность страниц (только оформление); карточки
  и страницы применяют дизайн к уже существующим экранам.
- Не добавляются новые зависимости для сетки/UI-кита (Bootstrap и т.п.).
- Без изменений БД, API, сущностей, правил доступа.

## Decisions

### D1. SCSS-токены в отдельном файле
Все значения палитры, размеры, радиусы и брейкпоинты — SCSS-переменные и
maps в одном файле `_tokens.scss`, компилируемом через Webpack Encore.
Альтернатива — CSS Custom Properties: отклонена, т.к. тема одна (светлая),
runtime-переопределение не требуется, а SCSS-переменные дают compile-time
проверку и привычны в Encore-сборке. Имена токенов зеркалят требования
спецификации и её семантику: `$color-action-orange: #d66a2b`,
`$color-success-green: #5e9e47`, `$color-info-blue: #20799e`,
`$gradient-cta`, `$bg-card-section: #f5f6f6`, `$container-max: 1360px`,
`$breakpoints: (576, 768, 992, 1200, 1400)`. Значения изначально взяты из
референсной гаммы и приглушены (снижена насыщенность) для 8-часовой работы:
оранжевый — только действие, зелёный — только статусы/успех, синий —
заголовки и навигация.

### D2. Компонентные Twig-шаблоны
Повторяемые элементы — отдельные partial-шаблоны в
`templates/components/`: `button.html.twig` (пилюли, варианты primary/
secondary/header-pair), `form_field.html.twig` (поле с нижним
подчёркиванием, единый стиль для Symfony Form), `card.html.twig`
(контактная карточка без иконок: имя + телефон + вторичные данные +
кнопка «Позвонить»), `offer_card.html.twig` (карточка предложения курса
с бейджем цены), `table.html.twig` (зебра без рамок), `modal.html.twig`
(зелёный градиент + backdrop), `header.html.twig` / `footer.html.twig`.
Альтернатива — symfony/ux-twig-component: отклонена как избыточная
зависимость для статичных элементов; при росте интерактивности возможен
апгрейд без смены токенов.

### D3. Лёгкая собственная сетка
Контейнер (max-width 1360px + центрирование) и брейкпоинты реализуются
собственными SCSS-утилитами, без Bootstrap. Альтернатива — Bootstrap Grid
(как в референсном дизайне): отклонена, чтобы не тянуть полный фреймворк;
нужны только контейнер и базовые колонки.

### D4. Самохостед-шрифты через Encore
Roboto Condensed (400/700) и Roboto — локальные woff2 с кириллицей и
латиницей через `@font-face`, `font-display: swap`, подключение через
Encore (`@fontsource` или ручные `@font-face` в SCSS). Тело текста — Roboto
15px, таблицы и заголовки — Roboto Condensed (16px/28px), сохраняя
«характер» референса при рабочем масштабе.

### D5. Автоматическая верификация соответствия
Каждый проверяемый сценарий спецификации покрывается Playwright-проверкой
(проект уже использует Playwright e2e): вычисленные стили (hex фонов,
градиенты, размеры, отсутствие box-shadow) и скриншот-сверка страниц.
Токены — источник значений, поэтому проверки читают скомпилированный CSS
и сверяют с hex-значениями из спецификации (зеркально, см. D1).

### D6. Доступность поверх референса
Референс не задаёт `:focus`-состояний; добавляются обязательные фокус-стили:
поле с подчёркиванием при фокусе утолщает линию с 2px до 4px без смены
цвета (требование спецификации «Формы»); кнопки — фокус-кольцо. Это
дополнение закрывает a11y-риск «невидимых» полей.

### D7. Единый base-шаблон для всех страниц
Все страницы (вход, welcome page, дашборд, списки, формы) рендерятся через
единый base-шаблон с общими шапкой, подвалом, палитрой и компонентами.
Никакая страница не получает особого оформления — включая страницу входа
(требование «Единый стиль всех страниц»).

### D8. Мобильные вызовы (браузеры и WebView приложения)
Интерфейс может открываться в мобильном приложении (WebView) и мобильных
браузерах, где кнопка вызова критична. Все телефонные поверхности —
кнопка «Позвонить» и `tel:`-ссылки (карточки, таблицы, шапка) — вызывают
системный набор номера (стандартный `tel:` URL — рабочий и в WebView, и в
браузере); никакие перехваты/модальные диалоги звонок не блокируют.
Кнопка «Позвонить» получает тач-цель минимум 44×44px (WCAG 2.5.5/2.5.8),
включая мобильную ширину. Прокручиваемая шапка и карточки сохраняют
доступность кнопки на всех брейкпоинтах (уменьшается padding, не
видимость). Альтернатива — плавающая (floating) кнопка вызова на
мобильной ширине: отклонена как дублирующая существующий CTA в шапке и
карточках; добавляется при подтверждённой в приложении необходимости.

## Architecture

Лёгкий компонентный уровень представления (ASCII, lightweight C4,
предположения: проектируемая система, формат ASCII):

```text
+----------------------------------------------------------------------------------+
|                        Web App (Symfony + Twig + Encore)                         |
|                                                                                  |
|  +------------+  рендер  +-------------------+  использует  +-----------------+  |
|  | Controllers| -------> | base.html.twig    | ------------> | components/*    |  |
|  +------------+          | (единый шаблон:   |              | .twig (button,  |  |
|                          |  header, footer,  |              |  field, card,   |  |
|                          |  welcome, lists,  |              |  offer_card,    |  |
|                          |  forms, login)    |              |  table, modal,  |  |
|                          +-------------------+              |  header/footer) |  |
|                                          |                  +--------+--------+  |
|                                          v                           |           |
|                          +-------------------+                     |           |
|                          | assets/scss/      | <------------------+ (используют  |
|                          |  _tokens.scss     |    переменные       |  токены)    |
|                          |  components/*.scss |    токенов          |             |
|                          +-------------------+                     |             |
|                                          |                          |             |
|  +-------------------+   Encore build   v                          v             |
|  | Compiled CSS/JS   | <-------------- public/build/  (webpack encore)            |
|  +-------------------+        (сборка — изменение asset-pipeline-setup)          |
|                                                                                  |
|  Проверка: Playwright e2e (computed styles + скриншоты) сверяет                   |
|  скомпилированный CSS с hex-значениями спецификации.                              |
+----------------------------------------------------------------------------------+
```

Диаграмма — упрощение для проектируемого уровня представления:
контроллеры рендерят страницы через единый base-шаблон, страницы собираются
из компонентов, компоненты и страницы используют SCSS-токены; сборку
выполняет Encore (из `asset-pipeline-setup`); проверка — Playwright по
требованиям спецификации.

## Risks / Trade-offs

- [Дрейф значений между спецификацией и SCSS] → Токены — единый источник
  значений (D1); Playwright-проверки (D5) сверяют скомпилированный CSS с
  hex-значениями спецификации и падают при расхождении.
- [Поля-подчёркивания без рамок снижают доступность] → D6: линия 2px
  утолщается до 4px при фокусе; контраст плейсхолдера/текста `#d66a2b` на
  белом проверяется в e2e.
- [Мягкие тона ниже по контрасту маркетинговых] → проверка контраста
  (белый текст на градиентах — крупные bold-элементы) включается в e2e.
- [Вес шрифтов при самохостинге] → только woff2, `font-display: swap`,
  подмножества (cyrillic/latin).
- [Зебра-таблицы без hover затрудняют чтение длинных списков] → строка
  остаётся активной для клика по всей ширине (аффорданс), hover не вводится
  ради соответствия спецификации.
- [Зависимость от сборки активов] → `asset-pipeline-setup` применяется
  первым; без него стили не компилируются.
- [Объём правок существующих Twig-шаблонов при применении] → применение
  идёт слоями: токены → компоненты → страницы; каждый слой проходит
  e2e-проверку до перехода к следующему.
- [WebView/браузер могут не открыть `tel:` без нативной обработки]
  → `tel:` обрабатывается системой на всех мобильных платформах; если
  в будущем приложение перехватывает deep-ссылки, ссылка остаётся
  доступной и копируемой (видимый номер в карточке/таблице), звонок
  дублируется кнопкой.
- [Тач-цель 44px на мобильной ширине при компактной шапке] → padding
  кнопки «Позвонить» на мобильных не уменьшается ниже 44px высоты;
  проверяется в e2e на брейкпоинте 576px.

## Migration Plan

1. Слой токенов (`_tokens.scss`) + шрифты; заглушка применения — welcome
   page. Верификация: e2e токенов. Требует применённый `asset-pipeline-setup`.
2. Компоненты (кнопки, поля форм, карточки, таблицы, модалки, шапка/подвал).
   Верификация: e2e компонентов.
3. Применение к страницам: welcome page → формы и страница входа (в едином
   шаблоне) → списки/таблицы → контактные карточки → модальные окна →
   шапка/подвал на всех страницах. Верификация: полный e2e-прогон +
   скриншот-сверка.
4. Откат: git-revert слоя; токены/компоненты обратимы без миграций БД.
