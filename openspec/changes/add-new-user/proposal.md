## Why

Администратору необходима возможность создавать пользователей системы.
Сейчас в спецификации `access-control` фигурируют сценарии создания
пользователей (например, «Мария Смирнова»), но формальная процедура создания
пользователя и поля имени/фамилии не выделены в отдельную возможность. Это
блокирует онбординг менеджеров и администраторов в B2B Call CRM.

## What Changes

- Добавляется возможность создания пользователя администратором с
  обязательным `email` и необязательными полями `name` (имя) и `surname`
  (фамилия). Пароль не задаётся при создании — пользователь устанавливает
  его позже (через сброс пароля / приглашение).
- Создание пользователя доступно только аутентифицированному администратору;
  менеджеры и анонимные пользователи не могут создавать пользователей.
- При создании пользователя администратор указывает роль (`admin` или `manager`)
  из фиксированного набора (ADR-0009).
- Поля `name` и `surname` MAY быть необязательными; система принимает создание
  пользователя без имени/фамилии. Обязательные поля — `email` и `role`.
- Для пользователя с ролью `manager` автоматически создаётся персональная группа
  `user-<id>-group` (ADR-0005); для `admin` группа не создаётся (ADR-0008).
- Администратор SHALL иметь возможность удалять любого пользователя
  (кроме самого себя); при удалении `manager` персональная группа
  `user-<id>-group` SHALL быть удалена (ADR-0005).
- Добавляется страница списка пользователей `/admin/users` для
  администратора, показывающая email, имя, фамилию, роль и кнопку удаления.

## Capabilities

### New Capabilities

- `new-user`: Возможность создания пользователя администратором с
  обязательным `email` и необязательными полями имени и фамилии,
  обязательным назначением роли из фиксированного набора.
- `delete-user`: Возможность удаления пользователя администратором;
  при удалении `manager` персональная группа `user-<id>-group`
  удаляется (ADR-0005).
- `admin-user-list`: Страница списка пользователей `/admin/users` для
  администратора с отображением email, имени, фамилии, роли и
  кнопками управления (удаление).

### Modified Capabilities

_None._ Назначение ролей и проверка доступа остаются в `access-control`; новая
возможность покрывает только процедуры создания, списка и удаления
пользователя.

## Impact

- **Код**: новый контроллер `UserController` (Symfony) с эндпоинтами
  list/create/delete; формы с полями `email` (обязательное), `name`,
  `surname` (необязательные) и `role` (обязательное). Сущность
  `User` получает поля `name` и `surname`.
- **БД**: миграция Doctrine, добавляющая nullable-колонки `name`,
  `surname` в таблицу пользователей. Миграция на изменение FK
  `OrganizationGroup.owner_user_id` на `CASCADE`.
- **API/UI**: новые страницы `/admin/users` (список), `/admin/users/new`
  (создание), `DELETE /admin/users/{id}` (удаление), все защищены
  ролью `admin`.
- **Зависимости**: ADR-0003 (admin-manages-managers), ADR-0005
  (personal group), ADR-0008 (admin scope), ADR-0009 (fixed roles);
  спецификация `access-control` используется как есть.
