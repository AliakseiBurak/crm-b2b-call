# ADR-0011: Владение группами через created_by вместо личных групп

- **Status:** accepted
- **Date:** 2026-09-08
- **Supersedes:** ADR-0005 (полностью), ADR-0003 / ADR-0006 / ADR-0007 (в части правил личной группы `user-<id>-group`)

## Context

Модель личных групп (`user-<id>-group`, ADR-0005) ограничивала менеджеров:
группы создавались только системой, текли в UI как деталь реализации и служили
пассивным механизмом доступа. OpenSpec-изменение `organization-groups` переводит
группы в разряд рабочего инструмента менеджера.

## Decision

Личные группы упраздняются. В таблице `organization_group` появляется колонка
`created_by` (FK → `user`, nullable). Владелец группы — её создатель:

- менеджер имеет полный CRUD-доступ к группам, где `created_by = self`, и
  управляет их составом (`OrgGroupMembership`);
- область доступа менеджера = организации групп, **созданных им**, + организации
  **назначенных** ему групп (`GroupAssignment`);
- администратор по-прежнему видит и управляет всеми группами и назначениями,
  личной группы у него нет (ADR-0008 сохранён);
- при удалении менеджера администратор выбирает судьбу каждой его группы:
  переназначить администратору (`created_by` := admin) или удалить;
- миграция `Version20260906000000` удаляет легаси-группы (`type = 'user'`),
  организации без групповой принадлежности остаются безгрупповыми.

## Alternatives considered

- Скрывать личные группы из UI менеджеров — отклонено: остаётся overhead
  поддержки и путаница у администратора.
- Новый столбец `type` для различения владельцев — отклонено: `created_by`
  достаточно, легаси-типы удаляются.

## Consequences

- Положительно: группы — полноценный инструмент менеджера; модель проще
  (нет спец-кейса личных групп).
- Отрицательно: организация, созданная менеджером без выбора группы, попадает
  вне его области видимости (назначения групп администратором пока делаются на
  уровне данных). Это временный разрыв, закрываемый активными изменениями
  `organization-visibility` (прямые гранты видимости) и
  `organization-group-assignment` (UI назначений).
- Follow-up: тексты спецификаций `access-control`, `organizations`, `contacts`,
  `dashboard`, `user-*` приведены к новой формулировке области доступа.
