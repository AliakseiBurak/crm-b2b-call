# ADR-0005: Собственная группа менеджера (user-<id>-group)

- **Status:** accepted
- **Date:** 2026-08-10

## Context

Согласно спецификациям `access-control` и `organization-groups` менеджеры
отвечают за свои организации, а распределение организаций между менеджерами
выполняется через группы. Возникает вопрос: как организации менеджера попадают
в его зону ответственности и как отличить группу, принадлежащую менеджеру, от
групп, созданных администратором.

## Decision

Каждому менеджеру при создании пользователя автоматически создаётся
собственная группа организаций с именем `user-<id>-group` (например,
`user-7-group`). Организации, создаваемые менеджером, автоматически попадают
в его группу. Администратор группы не имеет: для администратора группы не
проверяются. Дополнительные группы (`type = custom`) создаются администратором
с именованными slug-именами (например, "Минский регион" → `minsk-region-group`)
и назначаются менеджерам через `GroupAssignment`.

## Consequences

- Менеджер всегда имеет гарантированную зону ответственности без ручной
  настройки.
- Группу менеджера нельзя удалить, пока существует менеджер, которому она
  принадлежит.
- Группы менеджера не назначаются другим менеджерам (иначе нарушится модель
  владения); для совместной работы используются custom-группы.
- Администратор не имеет собственной группы; проверка его доступа не обращается
  к группам.
- Access-control и organization-groups spec'и ссылаются на это решение.
