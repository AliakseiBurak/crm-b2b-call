# ADR-0004: Модель взаимодействия — обзвон

- **Status:** accepted
- **Date:** 2026-08-12
- **Updated:** 2026-09-03 (change call-result)

## Context

Основной рабочий цикл менеджера — обзвон организаций с целью предложить
курсы, зафиксировать результат (рассылку, сделку, следующий звонок) и по
итогам запустить рассылку. Нужно определить сущность `Call` и модель обзвона.

## Decision

Звонок — сущность `Call` с полями: организация, контакт, дата
(`scheduled_at`), факт звонка (`made_at`, `made_by`), заметки, отметки
«сделка» (`is_deal`) и «нет ответа» (`is_no_answer`), ссылка на следующий
звонок (`next_call_id`), ссылка на последнюю рассылку с этого звонка
(`campaign_id` → `Campaign`, ON DELETE SET NULL) и дата создания.
`next_call_id` — ID **вновь созданного** `Call`, у которого `scheduled_at` в
будущем.

**Результат звонка — независимые действия**, а не enum и не отдельная
сущность `CallResult`:

- **Рассылка** — выбор любой кампании кроме `archived` создаёт или заменяет
  `CampaignRecipient`; на звонке фиксируется `campaign_id` последнего письма;
- **Следующий звонок** — дата в будущем создаёт новый `Call` и записывает
  `next_call_id` (один раз; правки — через карточку следующего звонка);
- **Сделка** (`is_deal`) и **нет ответа** (`is_no_answer`) — липкие отметки на
  `Call`.

Отказ от рассылки (удаление адресата) **не** выполняется из результата звонка —
только на странице адресатов кампании.

Действия результата допустимы только при заполненных `made_at` и `made_by`.
Пустое поле рассылки не меняет адресатов.

При замене адресата в запущенной кампании (`launched_at` задан) —
`replacementCount + 1`, новый `pending`, flash о повторной отправке.

**Планирование/напоминание.** Если `scheduled_at` у `Call` в будущем — это
будущий звонок, попадающий в планирование и напоминание. Псевдогруппа
«Звонки на сегодня» показывает звонки, запланированные на текущий день.
Псевдогруппа «Будущие звонки отключены» — организации без будущего звонка.

**Сортировка списка обзвона** (по выбору менеджера): по дате следующего
звонка (сначала просроченные), по дате последнего звонка, по дате последней
заметки.

**Сеанс обзвона.** Список формируется из группы организаций (own или
назначенной custom, см. ADR-0005–0006). Запуск → выбор организации (показ
карточки и её контактов) → менеджер самостоятельно звонит, оставляет заметки,
отмечает курсы и результат (рассылку/сделку/следующий звонок) → переход к
следующей организации. При обзвоне всех организаций или досрочном завершении —
переход к окну запуска рассылки/правки писем для организаций, отмеченных
результатом «рассылка».

**Удаление звонка** не удаляет `CampaignRecipient` и не удаляет порождённый
следующий звонок.

## Consequences

- Один звонок может дать одновременно рассылку, сделку, «нет ответа» и
  следующий звонок, либо только факт звонка.
- Рассылка с звонка — одна последняя (`campaign_id`), операции над
  `CampaignRecipient` — побочный эффект действия.
- Факт звонка всегда зафиксирован (кто и когда) независимо от результата.
- Следующий звонок — новый `Call` с датой в будущем; связь через
  `next_call_id` с ON DELETE SET NULL.
