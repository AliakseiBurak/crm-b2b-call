# ADR-0005: Фиксированный набор ролей (без CRUD ролей)

- **Status:** accepted
- **Date:** 2026-08-11

## Context

PRD §2.10 и §3.7 определяют роли как фиксированный enum: admin, manager,
operator. При этом §4.5 вводит CRUD-эндпоинты ролей (`POST /api/roles`,
`PUT /api/roles/{id}`, `DELETE /api/roles/{id}`) — прямое противоречие внутри
исходного продукт-документа. Модель доступа (ADR-0001–0004) и спецификации
`access-control` и `organization-groups` построены на фиксированном наборе ролей.

## Decision

Набор ролей **фиксирован**: admin, manager, operator. Система не поддерживает
создание, изменение и удаление ролей; эндпоинты Roles CRUD из PRD §4.5
**не реализуются** и трактуются как ошибка продукт-документа. Роль назначается
пользователю из фиксированного набора. Правило зафиксировано в спецификации
`access-control`.

## Consequences

- Простая и предсказуемая модель доступа: проверка роли не зависит от данных.
- Будущее требование кастомизации ролей потребует новой ADR, superseding-этой.
- Спецификация `access-control` ссылается на это решение.
