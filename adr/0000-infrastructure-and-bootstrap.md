# ADR-0000: Инфраструктура и начальная загрузка проекта

- **Status:** accepted
- **Date:** 2026-08-12

## Context

Проект стартует с пустого репозитория: нет кода, окружения и данных. Для
разработки модулей (организации, контакты, обзвон, рассылки) требуется
воспроизводимое локальное окружение, рабочее Symfony-приложение и данные для
ручной проверки сценариев звонков.

## Decision

Создаётся `docker-compose` с контейнерами: `php` (Symfony), `mysql` (БД),
`mailpit` (dev-SMTP, для приёма писем), при необходимости `nginx`. Зависимости
устанавливаются через Composer. Поднимается пустой проект Symfony (текущая
версия, совместимая с PHP 8.2+), подключаются Doctrine ORM и Symfony Mailer.

Выполняется начальная миграция (создание схемы БД) и загрузка фейковых данных
(fixtures): пользователи (admin, менеджеры), группы организаций
(`user-<id>-group`, custom), организации, контакты и запланированные звонки —
чтобы можно было сразу проводить обзвон и отправлять тестовые рассылки.

## Consequences

- Любой разработчик получает рабочее окружение одной командой
  (`docker compose up`) без ручной настройки.
- Данные для звонков (организации, контакты, будущие звонки) доступны сразу
  после загрузки fixtures.
- Отправка писем в dev идёт через Mailpit, реальный SMTP настраивается позже
  (см. ADR-0010).
- Инфраструктурные решения (версии образов, имена сервисов) фиксируются в
  `docker-compose.yml` и `composer.json`.
