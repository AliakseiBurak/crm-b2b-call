# ADR-0006: OpenSpec — единый источник истины (PRD удаляется)

- **Status:** accepted
- **Date:** 2026-08-11

## Context

Исторически требования исходили из `docs/source/PRD.md`, а OpenSpec-спецификации
ссылались на него («Источник: PRD.md §…»). Спецификации возможностей были
приведены в соответствие с PRD, внутреннее
противоречие о ролях разрешено (ADR-0005). Двойной источник истины (PRD + OpenSpec)
создаёт риск рассинхронизации. Требования из PRD, не вынесенные в возможности,
сознательно откладываются (реестр ниже) и не должны молча теряться.

## Decision

**OpenSpec — единственный источник истины** для B2B Call CRM. `docs/source/PRD.md`
и `docs/source/PRD_WORKFLOW.md` удаляются;
спецификации возможностей (`openspec/specs/`) и ADR (`adr/`) — авторитетны.
Ссылки «PRD §…» в контексте ADR-0001–0004 заменяются ссылками на спецификации
(`access-control`, `organization-groups`) — осознанное, одобренное пользователем
отклонение от правила неизменяемости ADR, ограниченное секцией Context.

**Реестр отложенных пробелов** (будущая работа, вне текущего скоупа):

| Пробел | Источник (PRD) | Суть |
|---|---|---|
| Управление пользователями | §2.10 | CRUD пользователя, связь `own_group_id`; сейчас покрыто частично в `access-control`/`organization-groups` |
| NFR: доступность | §7 | 99.5% |
| NFR: резервное копирование | §7 | ежедневно |
| NFR: аудит-логирование | §7 | полное для аудита |
| CSRF-защита | §6.3 | помимо уже покрытых OAuth2/JWT и шифрования |

## Consequences

- Устранён риск рассинхронизации двух источников истины.
- Удаление PRD безопасно: требования либо в спецификациях, либо в реестре.
- Висячие ссылки «PRD §…» устраняются по всему репозиторию (specs, ADR,
  project.md, config.yaml, AGENTS.md).
- Реализация отложенных пробелов начнётся с новых change-предложений.
